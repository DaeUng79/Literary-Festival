# 양산시 독서문화축전 현장 운영 가이드

2026년 10월 17~18일 현장 담당자가 휴대폰에서 현재 업무, 담당자, 비고, 대체 장소를 확인하는 정적 웹사이트입니다. 서버·DB·유료 API 없이 GitHub Pages에서 사용할 수 있습니다.

## 포함된 기능

- 지금 업무: 한국 시간에 맞춰 현재 상세일정과 해당 시간대 업무분장을 표시합니다. 업무분장은 총괄·운영부스 등 카테고리별로 접고 펼쳐 확인할 수 있습니다
- 행사 전 첫 화면에는 축제 준비 문구 아래 첫 일정 3개를 시간순으로 표시하고, 바로가기는 일정 아래에 둡니다
- 17일 업무분장 / 17일 상세일정 / 18일 업무분장 / 18일 상세일정 / 18일 우천일정
- 출퇴근 안내: 중앙팀 07시, 그 외 08시 출근, 근무복·명찰·커피 쿠폰, 물품 세팅, 초과사전 및 인사랑 확인
- 시간 미리보기: 별도 탭에서 날짜·시간을 바꿔 일정과 업무분장을 확인합니다. 실제 업무 화면과 운영 모드에는 영향을 주지 않습니다
- 외부 폰트, 분석 추적, 외부 이미지, 런타임 라이브러리 요청 없음

## 바로 실행

이 폴더에서 Python 3으로 실행합니다. 웹사이트 운영에 Node.js는 필요하지 않습니다.

```sh
python3 -m http.server 8766 --directory dist
```

브라우저에서 `http://localhost:8766`을 엽니다. HTML 파일을 더블클릭하는 `file://` 방식은 JSON 로딩이 제한되므로 HTTP 서버를 사용하세요. 로컬 주소는 이 컴퓨터의 미리보기 주소이며, 배포 후 GitHub Pages 주소를 직원에게 공유하세요.

## GitHub Pages

배포 주소: https://daeung79.github.io/Literary-Festival/ (Pages 설정 및 첫 배포 완료 후 접속 가능)

최초 설정은 저장소 관리자가 Settings → Pages → Build and deployment → Source에서 **GitHub Actions**를 선택해야 합니다. 이후 GitHub Actions가 `main` 변경을 검증한 뒤 `dist`만 배포하고, 소스를 `main`에 푸시할 때마다 자동 재배포합니다. 엑셀 원본은 저장소에 올리지 않습니다.

## 일정 변경

빠른 수정은 `dist/data.json`의 해당 업무·담당자·비고를 수정하고 재배포합니다. 직원은 사이트 하단의 ‘최신 자료 새로고침’을 누르면 새 데이터를 받습니다. 현재 업무의 **시간 전환은 자동**, 배포된 **데이터 변경 확인은 수동 새로고침**입니다.

엑셀을 갱신한 경우 다음 명령으로 다시 가져올 수 있습니다. Python 표준 라이브러리만 사용합니다.

```sh
python3 scripts/import_workbook.py '/절대경로/근무분장(세부분장 포함).xlsx'
node --test
```

변환기는 현재 제공된 시트·열·행 구조에 맞춰져 있습니다. 시트 추가, 행 삽입, 구조 변경 시 변환기 매핑과 테스트도 함께 수정해야 합니다. 다시 가져오면 `data.json` 직접 수정은 덮어씁니다. 출퇴근 안내는 변환기 하단 `commute`, 날짜는 변환기의 행사일 필드에 있습니다.

## 시간 및 우천 표시 규칙

- 기기 시계를 `Asia/Seoul`로 변환합니다. 기기의 자동 날짜·시간 설정을 권장합니다.
- 시작 시각은 포함, 종료 시각은 제외합니다. `13:20~13:40`은 13:20부터 13:39까지 진행 중입니다.
- 종료 시각이 없는 `13:00~` 업무는 **시작 후 15분간 시작 알림**으로 표시합니다. 이후 ‘시작 시각 지남’으로 표시하며, 완료됐다고 판단하지 않습니다. 상세일정에서는 항상 조회할 수 있습니다.
- 원본의 오전 10~14시, 오후 13~17시를 그대로 유지합니다. 13~14시에는 두 조가 표시됩니다.
- 양쪽 교대에 공통 배치된 담당자는 10~17시 종일로 표시합니다. 행사별 실제 시간은 세부일정을 함께 확인합니다.
- ‘내 화면 일반/우천’ 선택은 **해당 브라우저에만 저장**됩니다. 자동 기상 판단이나 전체 직원에게 우천 전환을 방송하는 기능은 없습니다. 현장 공지에 따라 각자 전환합니다.
- 17일 우천 시트는 원본에 없으므로 17일에는 일반 일정만 표시합니다.
- 18일 우천은 우천 시트의 일정과 대체 장소를 사용합니다. 일반 일정의 야외 지시를 자동으로 섞지 않습니다.
- 인터넷이 끊겨도 이미 연 화면에 로드된 데이터는 계속 표시합니다. 첫 접속·새로고침에는 연결이 필요합니다. 오프라인 앱 설치나 푸시 알림은 제공하지 않습니다.

## 원본과 확인사항

엑셀 5개 시트에서 61개 업무분장 카드, 63개 시간순 일정(일반 52개·우천 11개)을 구성했습니다. 사용자가 제공한 출근 알림 6개(17일 일반·18일 일반·18일 우천의 07시/08시)를 추가해 총 69개 일정입니다.

- 원본은 2026년·17일(토)·18일(일)로 표기되어 있습니다. 요청일 2026.10.15를 기준으로 10월 17~18일로 설정했습니다.
- 17일 `15:4 5~` 표기는 15:45로 정규화했습니다.
- ‘시장님/부시장님’, 대기표 안내 12:58과 입장 일정 12:57의 차이는 원문대로 유지했습니다. 현장 담당자 확인이 필요합니다.
- 퇴근 시각, 직원 주차·셔틀, 차출경비·대체휴무 세부 기준은 미제공이므로 확인 필요로 안내합니다. `근무자 제외` 문구도 제공된 표현 그대로 유지했습니다.
- 공개용 데이터의 차량번호는 비공개 처리했습니다. 업무상 필요한 직원 이름은 포함되어 있습니다. 공개 Pages와 공개 저장소에서는 누구나 이 데이터를 볼 수 있습니다. `noindex`는 검색엔진 노출을 줄이기 위한 표시이며 접근제어가 아닙니다.
- 공개 사이트에는 업무상 필요한 직원 이름이 포함되어 있습니다. 공유 전에 공개가 적절한지 확인하세요.

## 10~20명 동시접속 검토

사용 가능할 것으로 판단합니다. HTML/CSS/JavaScript/JSON을 처음 내려받은 뒤, 시계·현재 업무 계산·우천 전환은 각 휴대폰 내부에서 처리합니다. 초당 서버 호출, 데이터베이스 연결, 동시접속 세션이 없습니다.

정적 파일 전체는 0.2MB 미만입니다. 보수적으로 1회 로딩을 0.2MB로 잡으면 20명 동시 최초 접속은 약 4MB, 20명이 하루 100번씩 이틀간 전체 파일을 다시 받는 극단적인 경우도 약 800MB입니다. 실제 전송은 브라우저 캐시와 압축으로 줄어들 수 있습니다.

GitHub 공식 문서(2026.10.15 확인)는 사이트 최대 1GB, 월 대역폭 소프트 한도 100GB를 안내합니다. 이 사이트의 예상 사용량은 이보다 훨씬 작습니다. 동시접속 20명 자체의 성능 보장이나 실제 GitHub 배포 부하시험을 했다는 의미는 아닙니다. 현장 휴대폰 통신 품질과 GitHub 서비스 상태에는 영향을 받습니다.

- [GitHub Pages 사용자 정의 배포 워크플로](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)

## 검증

`node --test`로 한국 시간·자정 날짜 전환, 시작/종료 경계, 현재 상세일정 표시 구간, 15분 알림, 오전·오후 중첩, 우천 분리·장소, 동시 업무, 병합 셀, 변환 건수·차량번호 비공개, 출근 안내를 확인합니다. Node.js 테스트 도구 외 추가 설치는 필요하지 않습니다.
